# Telegram-бот на сервере

Этот режим добавлен отдельно от локального экспортёра. Не использует Telegram-сессию
владельца, не меняет его архив и не требует `api_id`/`api_hash`. Работает через Bot API
в long polling: домен, TLS-сертификат и входящий HTTP-порт не нужны.

## Что умеет

- Раздельные базы групп и каналов, обработка новых сообщений и правок.
- Ответы на `@tg_channel_parse_bot вопрос`, `/ask вопрос` и ответы на сообщения бота.
- Русскоязычный поиск по словам с нормализацией исходного проекта и смысловой поиск
  через OpenAI `text-embedding-3-small`; ответы через Responses API, по умолчанию `gpt-4.1-mini`.
- Ответы содержат даты и ссылки на исходные сообщения; PDF ссылаются на страницы.
- PDF/DOCX до 20 МиБ, текстовые форматы до 1 МиБ. Оригиналы сохраняются при ошибках.
- Сохранённая на диске очередь обновлений, повтор временных ошибок, единственный
  процесс через файловую блокировку и остановка по SIGTERM.

Тексты индексируемых сообщений и документов отправляются в OpenAI для эмбеддингов.
В запрос ответа отправляются вопрос и найденные фрагменты только текущего чата;
для Responses API задан `store=false`. API оплачивается отдельно. В личных сообщениях
бот показывает справку и не выдаёт содержимое групп.

## Ограничения Telegram и первой версии

Бот получает сообщения только после добавления и включения сбора. Bot API не умеет
выгружать старую историю и не сообщает об удалённых сообщениях: сохранённые копии
остаются. Telegram держит недоставленные обновления не дольше 24 часов; при длительном
простое возможны пробелы. Это не полный архив истории.

В канале бот должен быть администратором с правом публикации. Вопросы там могут
публиковать администраторы. Для подписчиков используйте группу обсуждения, добавив
бота и туда; канал и группа имеют отдельные базы, автоматического обмена между ними нет.
Группу, преобразованную в супергруппу, нужно включить заново: у неё новый ID.

Фото, голосовые, видео, ZIP и внешние ссылки не скачиваются. OCR новых сканов и ASR
не включены. Скан без текстового слоя отмечается как требующий OCR. Документы
ограничены 300 PDF-страницами и 200 тысячами извлечённых символов; неполное извлечение
отражается в `/kb_status`. Готовый индекс исходного экспортёра можно импортировать
вместе с ранее распознанными материалами.

SQLite хранит корпус, FTS и векторы на диске. Смысловой поиск перебирает векторы
выбранного чата: для очень больших архивов потребуется отдельный векторный индекс.
Модель может ошибаться; источники в ответе доступны для проверки.

## Подготовка

1. В @BotFather создайте `@tg_channel_parse_bot`. Для группы отключите Group Privacy
   через `/setprivacy` и добавьте бота заново либо выдайте ему права администратора.
   Для канала достаточно прав администратора с публикацией.
2. Создайте отдельный ключ OpenAI с доступом к моделям ответов и эмбеддингов.
3. Сохраните токен и ключ в `.env.bot` из `.env.bot.example`. Этот файл исключён из Git.
   Не используйте `.env` исходного экспортёра. `BOT_ALLOWED_CHAT_IDS` ограничивает
   подключение указанными ID; без списка любой администратор может включить бота в своём чате.
4. Установите Python 3.12 и зависимости:

```bash
uv sync --frozen --python 3.12 --extra bot
.venv/bin/python -m tg_knowledge.bot --env .env.bot run
```

Бот проверяет своё имя и отсутствие чужого webhook. Текущий webhook не удаляется.
Токен, ключи, исходные тексты и URL запросов с токеном не выводятся в журнал.

## В Telegram

Добавьте бота и отправьте от администратора `/kb_on@tg_channel_parse_bot`.
Эта команда включает сохранение и сообщает, какие данные отправляются в OpenAI.
С этого момента новые сообщения и поддерживаемые документы индексируются автоматически.
Команда `/kb_status@tg_channel_parse_bot` показывает ID чата и доступный объём.
Затем задайте вопрос: `@tg_channel_parse_bot что писали про аккумулятор 12V?`.

`/kb_off@tg_channel_parse_bot` останавливает сбор и ответы. Сохранённые данные остаются
на сервере. Правки сообщений обновляют поиск; собственные ответы бота не индексируются.
Ограничение — один вопрос от участника за 15 секунд. При ошибке сервиса ответов
сбор сообщений продолжается.

## Импорт прежней истории

Остановите бот на время импорта. Скопируйте папку архива на сервер защищённым способом,
не публикуя её в Git. ID исходного архива обязан совпадать с ID целевого чата:
нельзя перенести чужую переписку под видом другой группы.

```bash
.venv/bin/python -m tg_knowledge.bot --env .env.bot import-archive /path/to/archive --chat-id=-100123456
```

Читаются `archive.sqlite3` и, если он есть, `knowledge/index.sqlite3`. Исходные файлы
не меняются. Без готового индекса импортируются только тексты сообщений; сначала
обработайте документы исходным экспортёром, если они нужны в поиске. После запуска
и `/kb_on` эмбеддинги будут построены в фоне. Более свежие копии сообщений,
полученные ботом, повторный импорт не перезаписывает.

## Установка на Ubuntu/Debian с systemd

Команда запускается из чистой закоммиченной ветки и использует обычные SSH/SCP
(ключ SSH или запрос пароля). Серверу нужны Python 3.11–3.13, модуль `venv`, `pip`,
`useradd`, `runuser` и systemd. При отсутствии `venv` установите пакет `python3-venv`.

```bash
bash scripts/deploy-bot.sh root@your-server 22 .env.bot
```

Установщик создаёт отдельного пользователя `tg-knowledge-bot` и сервис:

- Код: `/opt/tg-knowledge-bot/releases/<commit>`; ссылка `current` на активный выпуск.
- Секреты: `/etc/tg-knowledge-bot/bot.env`, права `0640`, чтение только root и сервису.
- Данные: `/var/lib/tg-knowledge-bot`, права `0700`.
- Сервис: `tg-knowledge-bot.service`, автозапуск и перезапуск при сбое.

Другие сервисы и архив исходного проекта не затрагиваются. Установка проверяет
успешный polling нового процесса; при неудаче возвращает прежний выпуск и конфигурацию.
Данные общие между выпусками, первая версия не делает разрушительных миграций.

```bash
systemctl status tg-knowledge-bot
journalctl -u tg-knowledge-bot --since '10 minutes ago' --no-pager
sudo -u tg-knowledge-bot /opt/tg-knowledge-bot/current/.venv/bin/python \
  -m tg_knowledge.bot --data /var/lib/tg-knowledge-bot status --health
```

`status --health` возвращает код 1, если за 90 секунд не было успешного polling.
Поле `embedding_error` и очередь `failed` требуют проверки доступности API/лимитов.
После устранения причины `retry-failed` возвращает неудачные обновления в очередь.
Документы с ошибками извлечения сохраняются; для повторного извлечения исправьте
причину и отправьте документ заново либо обработайте его исходным экспортёром и импортируйте индекс.

Telegram не поддерживает ключ идемпотентности для отправки: при обрыве соединения
после приёма ответа Telegram или аварии сразу после отправки редкий дубль возможен.
Индексирование и повторная обработка входящих сообщений идемпотентны.

Для резервной копии используйте SQLite backup API и копию `media/`; не копируйте
работающий WAL-файл отдельно от базы. Резервные копии содержат личную переписку.

```bash
.venv/bin/python -m ruff check src tests
bash -n scripts/deploy-bot.sh scripts/install-bot.sh
```

Тесты изолированы от Telegram и OpenAI и не используют личную переписку.
